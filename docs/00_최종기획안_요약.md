## 1. 한 문장 정의

> 닷닷플래너는 한 번 입력한 기록을 Today·Weekly·Monthly Log에서 다시 적지 않고 배치·이동·완료·회고할 수 있는 개인용 로컬 퍼스트 플래너다.

단순한 투두리스트가 아니라, 날짜가 가까워질수록 기록을 더 구체적인 위치로 옮겨 가며 계획을 다듬는 구조다.

- `이달의 할 일`: 이번 달 안에 할 일을 날짜 없이 보관
- `Monthly Log`: 한 달의 일정과 흐름을 시각적으로 배치
- `Weekly`: 가까운 여러 날을 나란히 비교
- `Today`: 오늘 실행할 항목을 상세하게 관리
- `상세 패널`: 설명·하위 할 일·이미지·동영상 등 실행 맥락 보관

## 2. 타깃

**한국 플래너 유목민** — 플래너를 쓰고 싶지만 다음 이유로 정착에 실패하는 개인 사용자.

1. 기록과 수정이 번거롭다.
2. 계획이 틀어지면 시스템 전체를 다시 정리해야 한다.
3. 미완료가 실패처럼 쌓인다.
4. 화면마다 같은 내용을 다시 입력해야 한다.
5. 도구 관리 자체가 새로운 일이 된다.

협업 업무 관리, 담당자 배정, 활동 로그, 조직용 간트차트가 핵심인 제품은 아니다.

## 3. 제품 원칙

### 닷닷 3원칙

1. 시작 전에 많은 선택을 요구하지 않는다.
2. 시스템 유지를 위한 별도 관리 노동을 요구하지 않는다.
3. 미완료를 죄책감이나 실패로 표현하지 않는다.

### 구현 판정 기준

새 기능은 다음 질문을 통과해야 한다.

1. 기록·수정·복구를 더 빠르게 만드는가?
2. 같은 기록을 여러 화면에서 재입력하지 않게 하는가?
3. 계획이 바뀌어도 이어갈 수 있게 하는가?
4. 사용자에게 새로운 설정·분류·유지 부담을 만들지 않는가?
5. 기존 데이터와 조작 문법을 깨지 않는가?

## 4. 현재 구현된 핵심 구조

### 기록과 보기

- 할 일·일정·메모·구분선
- 날짜 범위와 시작·종료 시간
- Today·Weekly·Monthly Log 간 이동
- Calendar와 Today가 공유하는 `이달의 할 일`
- 과거·현재·미래 날짜 조회와 수정
- 음력 표시
- 라이트·다크 테마

### 계획 복구

- 미완료 할 일 자동 이월
- 완료 항목은 이월 대상에서 제외
- 다일 할 일은 종료일 이후에만 이월
- 이월 항목의 원 날짜·완료 occurrence 보존
- 휴지통 소프트 삭제와 복원
- Undo/Redo

### 유연한 배치

- Daily·Weekly·Monthly Log 드래그 이동
- Monthly Log의 실시간 하드 스냅
- 단일·가로·세로·대각선 범위 생성
- 기존 일정을 감싸는 마퀴 다중선택
- Weekly 1~14일 표시와 8~14일 균형 분할
- 그룹·정렬·다중 선택·복사·붙여넣기

### 연결과 맥락

- 날짜 없는 월간 마스터와 날짜 배치본 연결
- 연결 인스턴스 복사
- 제목·유형·설명·하위 할 일·프로젝트 공유
- 날짜·시간·순서·날짜별 그룹은 인스턴스별 독립
- 전역 프로젝트 최소 축
- 상세 패널의 블록 편집, 이미지·동영상 첨부

### 데이터 안전

- localStorage 저장
- IndexedDB 첨부 파일 저장
- 저장 대상별 독립 실패 배너
- 손상 데이터 원본 백업과 개별 격리
- 저장 스키마 버전·마이그레이션 훅
- 교차 탭 수정 충돌 감지
- JSON 내보내기
- 프로젝트를 포함한 export·마이그레이션 백업

## 5. 현재 구현 상태의 중요한 해석

### Monthly Log의 18칸은 시간이 아니다

현재 가로 18칸은 사용자가 일정을 시각적으로 배치하는 **임의 레인**이다.  
`startTime`·`endTime`과 Monthly Log의 가로 위치는 아직 연결되어 있지 않다.

따라서 24시간 축은 단순 라벨 추가가 아니라 다음을 결정한 뒤 별도 기능으로 구현해야 한다.

- 기존 18칸 보기와 병존할지
- 시간 없는 일정을 어디에 둘지
- 다일 일정을 연속 구간 또는 매일 반복으로 볼지
- 기존 18칸 데이터를 어떻게 보존할지
- 고정 시간 경계 23개와 자유 구분선을 어떻게 공존시킬지

## 6. 검수 상태

최신 수정 묶음 보고:

- Playwright + Chromium 누적 `144/144` 통과
- `node --check app.js` 통과
- 전 구간 콘솔 오류 `0건`
- 실행하지 못한 요청 테스트 없음

최근 완료:

- JSON 내보내기·마이그레이션 백업에 프로젝트 포함
- Monthly Log 상단 불필요 제목 제거
- 일정 입력창 중앙 정렬
- `Math.round + 0.15 데드존` 하드 스냅
- 자동 스크롤 중 마퀴 좌표계 오류 수정
- 목표 일정 두 개 정확 선택·범위 밖 일정 제외 검증

자동 테스트가 통과했더라도 실제 마우스·터치·대용량 미디어 감각은 사용자 수동 확인 대상으로 분리한다.

## 7. 남은 작업

### 사용자 수동 재검증

- 날짜 라벨 클릭 후 선택·입력 포커스
- 위→아래·아래→위 범위 선택 시 입력창 위치
- 셀 너비 확대 시 입력창 잘림 여부
- 음력 ON 상태 날짜 선택
- 종료일 첫 클릭 직후 휠 조작
- Today 연속 재정렬
- Weekly 8·9·10·13·14일 균형 배치
- 휴대전화 터치 드래그
- 동영상·대용량 첨부·저장 용량 초과

### 정책 결정 후 구현

- 24시간 축과 종일·시간 미정 트랙
- 기존 18칸 보기와 24시간 보기의 관계
- 자정을 넘는 다일 시간 일정
- JSON 가져오기와 첨부 파일 완전 백업
- 3개월 이상 누적 미완료 정책
- 열별 개별 너비
- 프로젝트 전용 화면·검색·태그·필터
- AM/PM 없는 숫자 시간 입력 해석

## 8. 최종 방향

닷닷플래너의 경쟁력은 기능 수가 아니라 다음 루프의 마찰을 줄이는 데 있다.

> 기록한다 → 가까운 시간 범위에서 다시 본다 → 필요하면 옮긴다 → 완료한다 → 기록이 사라지지 않는다.

새 기능은 이 루프를 강화할 때만 채택한다.  
기존 동작을 깨거나 시스템 관리 부담을 늘리는 확장은 넣지 않는다.
